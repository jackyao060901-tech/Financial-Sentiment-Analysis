# 雪球(Xueqiu)ST 股舆情采集器 + 实时看板

采集雪球上指定股票的**讨论帖**(标题/正文/时间/作者/评论/赞/转发/阅读数),
**目标:从 2020 年至今**,并配一个仿老师 `ST Guba Scraper` 的**实时进度看板**。

> ⚠️ **必须在本地 / 住宅 IP 的电脑上跑**(如老师那台),不要在机房/云服务器/本项目云沙盒跑。原因见下。

---

## 一、为什么必须"浏览器 + 本地"(先看这个,省得踩坑)

采集前做过完整调研,结论如下(都是实测):

1. **雪球讨论页受阿里云 WAF 保护**:直接用 `requests` 只会拿到 WAF 挑战页,拿不到数据。
2. **雪球有个"公开搜索接口"能绕过 WAF**(先访问 `xueqiu.com/service/csrf` 拿 `xq_a_token`,
   再打 `api.xueqiu.com/query/v1/symbol/search/status.json`),**但它硬性上限约 1000 条/只**——
   实测 8 只 ST 股 1000 条全部只能回溯到近一两年(得润甚至只到最近 1 个月),**到不了 2020**。
   所以纯接口这条路**满足不了"2020 至今"的要求**。
3. **~~网页下滚能突破 1000~~ → 本地实测已证伪**:曾设想用浏览器打开个股页、顺网页"讨论"
   无限下滚突破 1000。**2026-07-09 本地住宅 IP + 登录实测(见 §六):网页讨论区后台用的
   就是那个 ~1000 条封顶的搜索接口,没有更深的接口**。登录只把 maxPage 50→100、总量仍锁 ~1000,
   活跃股回溯到约 2023,**到不了 2020**。→ 雪球定位为"近千条";2020 深历史由东财股吧覆盖。
4. **为什么仍要住宅 IP + 浏览器**:机房/云 IP 会被雪球更严风控、WAF 更爱挑战,且登录态要靠浏览器;
   住宅 IP(家里宽带、老师那台)基本不触发。本项目云沙盒既是机房 IP、浏览器又联不了网,
   所以雪球**在沙盒里跑不了**——用 API 模式先取近千条,浏览器/登录深翻需本地。

## 二、装 & 跑

```bash
pip install -r requirements.txt
playwright install chromium          # 本地首次需要(下载浏览器内核)

# ★★ 第一步:先自测!(强烈建议)★★
# 跑一只股票约90秒,看能不能翻过2023、往2020走。确认能到2020再长跑,别盲跑几小时。
python xueqiu_scraper.py --test 300301

# 第二步:确认能到2020后,正式采集(默认 STOCKS 里5只,深爬到2020)
python xueqiu_scraper.py
python xueqiu_scraper.py --since 2020-01-01     # 指定回溯日期
python xueqiu_scraper.py --proxy http://ip:port # 需要时挂代理(如老师的 freeproxy)
python xueqiu_scraper.py --export               # 只把 DB 导出成 CSV

# 看板(另开一个终端)
python dashboard.py                  # 打开 http://127.0.0.1:8000
```

**改股票名单**:编辑 `xueqiu_scraper.py` 顶部的 `STOCKS = [("300301","ST长方"), ...]`
(纯数字代码 + 名称),同时改 `dashboard.py` 顶部的 `WATCH`(带 SZ/SH 前缀)保持一致。

**像老师那样把看板分享成公网网址**(内网穿透,任选其一):
```bash
ssh -R 80:localhost:8000 serveo.net              # serveo,和老师同款
cloudflared tunnel --url http://localhost:8000   # 或 cloudflared
```

## 三、看板有什么

## 四、数据说明

存 **SQLite**(`data/xueqiu.db`,`post_id` 主键**自动去重**),`--export` 导出为
`data/xueqiu_{symbol}.csv`。字段:

| 字段 | 含义 | | 字段 | 含义 |
|---|---|---|---|---|
| post_id | 帖子唯一 id(去重键) | | reply_count | 评论数 |
| symbol / stock_name | 股票代码(SZ/SH)/ 名称 | | like_count | 点赞数 |
| title | 标题(多数帖无独立标题) | | retweet_count | 转发数 |
| text | 正文 | | view_count | 阅读数 |
| truncated | 正文是否被截断(1=是) | | fav_count | 收藏数 |
| author / user_id | 作者 / 作者 id | | source | 发布来源 |
| created_at | 发帖时间 | | url | 帖子链接 |

> **正文截断**:雪球长帖在列表里可能被截(`truncated=1`)。如需完整正文,可后续加"第二阶段"
> 逐帖请求详情补全(同老师股吧的思路);当前 `text` 已是列表返回的正文,多数够用。

## 五、特性 & 断点续采

- **去重**:`post_id` 主键,反复跑不会重复入库。
- **断点续采**:每只股票会从**已有最旧一条**的 id 作 `max_id` 继续往前翻——
  中途断网/关机都不丢已采数据,**下次再跑接着上次的位置**,不重复不遗漏。
- **每批入库**:抓一批存一批,进程被杀也只丢最后没存的那一小批。

## 六、能不能到 2020:**本地实测已盖棺(2026-07-09)——不能,雪球硬顶 ~1000 条**

> 本节结论**不是推断,是本地住宅 IP + 真实浏览器 + 登录态实测出来的**(诊断脚本
> `probe_endpoints.py` / `probe_capture.py` / `probe_deep.py` / `probe_count.py` 均在本目录,可复现)。

**关键事实链(三条独立路径,全部收敛到同一天花板)**:
1. **网页"讨论"区后台就是那个搜索接口**:抓包(`probe_capture.py`)证实,雪球个股页
   加载讨论用的是同域接口 `xueqiu.com/query/v1/symbol/search/status.json?...&sort=time&page=N`
   ——**没有另一个"更深"的股票时间线接口**,`stock_timeline.json` 未登录直接返回 0 条。
2. **登录只把 maxPage 从 50 抬到 100,但总量没变**:`probe_deep.py` 登录后逐页翻,
   maxPage=100、日期稳步回溯;但 `probe_count.py` 显示——
   - `count=10` → maxPage=100 → 1000 条;
   - `count=30/50/100` → 服务器**只回 19 条/页并把 maxPage 压回 50** → ≈950 条。
   - **加大 count 无效**:总量被服务器锁死在 ~1000。
3. **极限日期固定**:不同 count 跳到各自最后一页,最旧日期**都是 `2023-10-19`(ST长方)**;
   与未登录 API 模式(沙盒)得到的最旧日期**完全一致**。

**结论**:雪球公开可得 = **每只股票最近 ~1000 条**,活跃股大约回溯到 **2023 年**,
**到不了 2020,登录 / 加 count / 换游标都突破不了**。这也正是老师说的"**先爬前 100 页就行**"
(maxPage=100)。→ **2020 的深历史由东财股吧覆盖(`data/st_since2020/`,12 万条到 2020);
雪球负责近千条。分工明确,不必再为雪球到 2020 折腾。**

**已验证正确的部分(真实雪球数据实测)**:字段解析、SQLite 去重、断点续采、CSV 导出、
看板渲染、以及上面这套"能挖多深"的结论。

**自测命令**(仍保留,用来复核当天极限日期):
```bash
python xueqiu_scraper.py --test 300301   # 报告最旧到哪天(活跃股约 2023)
python probe_count.py --code 300301      # 登录后复核 maxPage/count 硬顶
```

## 七、别踩的坑

- **别在云服务器/机房 IP 跑**:WAF 更爱挑战、更易被封。用住宅宽带。
- **控制频率**:代码已内置 1.5–3s 拟人间隔;别改太快,雪球对高频敏感。
- **合规**:数据仅用于研究/课程用途。

## 八、备忘:两个方向的技术记录

**(A) 已采用老师验证过的浏览器打法**(`scrape_stock`):
- 有头模式 `headless=False` + 反检测(隐藏 `navigator.webdriver`、`--disable-blink-features=AutomationControlled`);
- **页面内 `page.evaluate` + `fetch()`** 调接口(带完整会话态,比 `page.request` 更稳);
- 仍按股票,用网页无限滚动的 `stock_timeline` 接口 + `max_id` 游标(与被卡 1000 的搜索接口不同,有机会更深)。

**(B) "按用户"方案(记下,暂不做)**:
- 老师 `guba-scraper/xueqiu_scraper.py` 的思路:调 `/v4/statuses/user_timeline.json?user_id=X&page=N`,
  **这个接口不卡 1000**(可翻数百页到很早),适合"抓某个大V的全部帖"。
- 但它是**按用户**、不是按股票;想用它补某股票到 2020,需先找出该股的高频用户再逐个拉、按 `$股票$` 标记筛,
  且**只能覆盖现役用户**(2020 发过、现在不发的人找不到)→ 补不全。**故暂缓,先按股票。**
- 实测:该接口在沙盒里第 1 页能取、第 2 页起报错(深翻需浏览器会话态);本地浏览器可行。
