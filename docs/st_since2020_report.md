## 三、关键发现:单 IP 会撞"限流墙"(实测,正是老师说的问题)

这次采集**亲测复现了"单 IP 被封"**,过程如实记录:

1. **一次只能深爬一只**:连续翻约 **150 页(~12,000 条)** 后,东财就对本 IP 限流——页面返回 200 但**内容变空**(不是 HTTP 错误,是软封)。
2. **深爬一只会"殃及"后面的**:第一轮先爬 ST长方(翻到 159 页),之后 ST和科/诺泰/得润从第 1 页就吃空页 = **IP 已被限流**。
3. **验证是"封"而非"没数据"**:限流期间单独重试这些股票仍是空;**过一会儿(IP 冷却)再试,立刻恢复正常返回 80 条/页**——证明是 IP 级限流,不是股票没帖子。
4. **冷却后换批再爬**:等 IP 恢复,才补到了 ST和科(直接爬到 2020-10)和后 3 只的近端数据。

**结论:要把 5 只都完整回溯到 2020,必须"换 IP"**——这与老师用梯子(tizi)换 IP、下一批换一次的做法完全一致。本仓库代码已预留 IP 池接口(见下),接上就能自动化。

## 五、如何补全到 2020(工程建议)

- **换 IP 分批**(最直接):每个 IP 深爬 1~2 只到 2020(约 150~500 页/只),被限流就换 IP 续爬。
  - 手动:梯子/代理换 IP(老师现用法);
  - 自动:`polite_get(..., proxy_pool=pool.get)` 接住宅代理池即可轮换(代码已支持,见 `crawlers/common.py`)。
- **断点续采**:按 `post_id` 去重(脚本已做),换 IP 后从上次最旧时间继续,不重复。
- **深度估算**:到 2020 约需 ST和科级别的 ~160 页(它已达标);活跃度更高的股(如得润)可能需数百页。
