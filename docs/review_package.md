## 1. 背景与目标

- **项目中心**:采集股票社区(东方财富股吧、雪球等)的舆情数据,为后续**投资者情绪分析
  (Investor Sentiment Analysis)** 打基础。
- **导师原话**:"调研雪球、东方财富股吧上的帖子、文章,看看怎么用爬虫爬下来……舆情分析是 data science 课题。"
  补充确认:"目前是拿数据就行,分析是后面的。"
- **第一阶段任务** = 广泛摸清各平台**能不能爬 / 怎么爬 / 值不值得爬**,做出**能跑的采集原型**,字段按后续情绪分析设计。
- **研究诚信**:实测写"实测",推断写"判断",预测改"基于当前观察";数据真实抓取,不用记忆编造,每条带 `url+crawl_time`。

## 2. 成果概览(第一阶段已定稿)

- **9 个平台已跑通并实采** + 雪球原型(共 10 个爬虫文件):
  东方财富股吧、东财个股新闻、新浪财经股吧、同花顺个股资讯、淘股吧、**韭研公社(游资研究,高价值)**、
  百度贴吧(App 接口,内容跑偏、价值低)、富途资讯(含正文,覆盖有限)、腾讯资讯(仅标题);雪球=Playwright 原型,需本地跑。
- **共调研 15 个平台/入口**(含难爬/不可达的),逐个给出最终结论。
- **样本**:`data/samples/` 共 **8 平台、约 356 条真实带正文样本**(5 只股票 + 韭研综合流)。

## 3. 各平台技术方法与结论(核心)

| 平台 | 能否爬 | 关键手法 | 登录/签名 | 研究价值(散户情绪) |
|------|:---:|------|:---:|:---:|
| 东方财富股吧 | ✅ | 列表页内嵌 `var article_list` JSON;正文详情页 `post_content` | 否 | **高**(首选) |
| 淘股吧 | ✅ | 个股页 `related-subject`→文章页 | 否 | 较高 |
| 韭研公社 | ✅ | Nuxt `__NUXT__`(UTF-8)单篇取标题+长正文 | 否 | **高**(游资研究) |
| 新浪财经股吧 | ✅ | GBK 静态表格 + 详情页 | 否 | 中低(活跃度低) |
| 东财新闻/同花顺资讯/富途/腾讯 | ✅ | 公开 JSON / 内嵌状态(资讯,部分仅标题) | 否 | 中低(新闻面) |
| 百度贴吧 | ✅ | Web 403→**App 接口+公开签名 `tiebaclient!!!`** | 签名 | **低**(个股吧多招聘/广告) |

| 金融界/和讯 | ❌ | 本环境代理连接失败(不可达) | — | — |

### 两个诚实的"踩坑"结论(方法学价值)
- **雪球**:纯 requests / Node / jsdom 均实测跑不通,需真浏览器;本云沙盒浏览器又穿不过出网代理 → 需本地跑。逆向 WAF 脆弱、不推荐。
- **百度贴吧**:换 App 接口能爬,但实采发现个股同名吧全是招聘/广告/卖货,**非炒股讨论** → "能爬≠值得爬"的实测反例。

## 4. 关键决策与取舍(请审查是否合理)

1. **先采集、不分析**(遵导师"先拿数据")。
2. **主攻东方财富股吧**:无登录、字段最全、量大、纯散户、好维护。
3. **字段先对齐后续分析**:统一 16 字段,避免"爬了没法用"。
4. **不硬刚难源**:雪球留本地(真浏览器)、同花顺社区/微博/财联社(签名/登录)暂缓——环境限制,非无价值。
5. **文本只轻清洗**:去标签/解码实体/压空白;股票标记、表情占位符保留待分析阶段决定。
6. **评价体系**:用定性等级(A/B/C)+ 定性维度,不用假精确数字;"研究价值"给了 5 条评判依据;并标注"实采 vs 判断"。
7. **规模化**:代码已预留 IP 池/代理接口(`polite_get(proxy_pool=)`);防封分层"限速→增量→IP 轮换→分布式"(见报告附录 D)。
8. **下一阶段路线设想**:情绪分析词典法起步(中文金融情感词典+jieba)→ FinBERT 中文 →(可选)LLM 打标。

## 5. 统一数据字段(schema)

```
platform, stock_code, post_id, title, content, author, author_id,
publish_time, read_count, comment_count, forward_count,
bullish_bearish, has_pic, has_video, url, crawl_time
```
- 做情绪分析至少需:`stock_code`、`title`/`content`、`publish_time`。拿不到的字段留空不臆造。

## 6. 已知局限(诚实记录)

1. 样本为**原型级**(每平台每股十余条),非全量。
2. **实采 vs 判断**:雪球/同花顺社区/微博的"数据丰富度"是判断,未实采。
3. **时间格式不统一**(新浪仅"MM月DD日"),合并前需归一化。
4. **资讯 ≠ 散户帖**(东财新闻/同花顺/富途/腾讯无阅读评论数)。
5. **富途正文覆盖有限**(约 5/30,不同文章结构)。
6. 未做跨源去重/转载识别;文本仅轻清洗。
7. **易碎性**:WAF/签名/SSR 类平台今天能跑不代表明天能跑(见维护成本、时效声明)。

def polite_get(session, url, ..., proxy_pool=None, **kwargs):
    for attempt in range(retries):
        try:
            if proxy_pool is not None:
                kwargs["proxies"] = proxy_pool()   # 每次取一个 IP,支持轮换
            resp = session.get(url, timeout=timeout, **kwargs)
            time.sleep(random.uniform(min_delay, max_delay))  # 频率控制
            return resp
        except requests.RequestException as e:
            time.sleep(2 ** attempt)               # 指数退避

## 8. 请复核的具体问题(审查者重点看这里)

1. **技术判断准确性**:雪球=新版阿里云 WAF 需真浏览器、同花顺社区/财联社=签名、微博=需登录、贴吧个股吧=内容跑偏——这些结论对不对?有无我误判、其实有更简单路径的?
2. **平台覆盖**:对 A 股散户舆情,平台选择是否合理?**还有没有更好、信息量更大的中文源被漏掉**?(已覆盖东财/雪球/淘股吧/韭研/新浪/同花顺/富途/腾讯/贴吧/微博/财联社/老虎/金融界/和讯/知乎/集思录)
3. **研究价值评判依据**(用户主体/围绕个股/连续更新/原创非转载/互动规模)是否站得住?权重是否合理?
4. **字段设计**:这套 16 字段对后续情绪分析够不够?还缺什么(点赞/IP 归属/情绪标签/是否原创)?
5. **规模化方案**(附录 D:限速→增量→IP 轮换→分布式 + DB 去重)是否完整、可落地?IP 池选型建议是否靠谱?
6. **代码健壮性**:内嵌 JSON / 正则 / GBK / 大括号配平 / App 签名 / Nuxt 解析,有无明显脆弱点或更稳写法?
7. **评价体系客观性**:定性 A/B/C + "实采 vs 判断"标注,是否已足够严谨?还能怎么更客观?
8. **下一阶段路线**:情绪分析"词典法→FinBERT→LLM"是否合理?中文金融文本起步用哪种更稳?
