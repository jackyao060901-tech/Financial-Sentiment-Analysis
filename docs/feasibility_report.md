# 各平台爬取可行性报告

> 第一阶段目标:广泛摸清各金融社区平台**能不能爬、能的话怎么爬**,并做出能跑的采集原型。
> 本阶段**不做情绪分析**,但字段按"以后要做情绪分析"来设计(见 `docs/data_schema.md`)。
> 侦察日期:2026-07-04。测试环境为云端(出网走代理),已实测各站可达。

## 结论速览

| 平台 | 可爬性 | 方式 | 需登录/Token | 反爬难度 | 状态 |
|------|--------|------|--------------|----------|------|
| 东方财富股吧 | ✅ 高 | 列表页内嵌 JSON | 否 | 低 | **已做成可跑爬虫** |
| 雪球 | ⚠️ 中低 | 接口 + 浏览器过 WAF | 需浏览器 cookie | 高(阿里云 WAF) | 已做 Playwright 原型 |
| 新浪财经 | 🔸 中 | 评论/资讯接口 | 部分需 | 中 | 初步评估,待深入 |
| 同花顺 | ⚠️ 中高 | 页面 + JS 渲染 | 部分需 | 中高(基础页 403) | 初步评估,待深入 |
| 淘股吧 | 🔸 中 | 传统论坛 HTML | 否 | 低~中 | 初步评估,待深入 |
| 微博财经 | ⚠️ 高难 | m.weibo.cn 接口 | 需登录 cookie | 高 | 暂不推荐第一版做 |

**推荐第一版主攻东方财富股吧**:最好爬、字段最全、无需登录、量大且都是散户,最贴合"散户舆情"这个目标。雪球质量高但要过 WAF,作为第二优先。

---

## 1. 东方财富股吧(推荐首选)✅

- **入口**:`https://guba.eastmoney.com/list,{股票代码}.html`,分页为 `list,{代码}_{页码}.html`。
- **关键发现**:列表页静态 HTML 里内嵌一段 `var article_list = {...}` 的 JSON,**每页约 80 条**,直接 `json.loads` 即可,无需解析 DOM,非常稳。
- **能拿到的字段**:帖子 id、标题、作者昵称/ id、**发帖时间(带完整年份)**、阅读数(post_click_count)、评论数、转发数、是否含图/视频,以及平台自带的 `bullish_bearish`(看涨/看跌标记 —— 以后可当情绪的免费参照)。
- **正文**:列表里没有正文,需再请求详情页 `/news,{代码},{帖子id}.html` 抽取(爬虫里 `--with-body` 开关)。
- **登录/Token**:**都不需要**。
- **反爬**:低。带常规浏览器 UA 即可,请求间隔 1~2.5 秒足够礼貌。
- **代码**:`crawlers/eastmoney_guba.py`(已实测跑通,样本见 `data/samples/`)。

## 2. 雪球 ⚠️

- **入口**:讨论接口 `https://xueqiu.com/query/v1/symbol/search/status?...&symbol=SZ000001&type=11`。
- **关键发现**:接口受**阿里云 WAF(JS 挑战)**保护。实测用 requests 先访问首页拿到 cookie(acw_tc/s/u)再请求接口,返回的仍是 WAF 挑战页(含 `aliyun_waf`/`_waf_` 字段)而非数据 —— **纯 requests 方案不可行**。
- **可行路径**:用真实浏览器(本环境已预装 Chromium + Playwright)先加载页面通过 JS 挑战,再在同一浏览器上下文请求接口或解析 DOM。原型见 `crawlers/xueqiu.py`(`fetch_via_browser`)。
- **能拿到的字段**:帖子 id、正文(text,HTML)、作者、发帖时间(毫秒时间戳)、阅读/评论/转发数。
- **登录/Token**:不用登录,但**必须有浏览器执行 JS 拿到的 cookie**。
- **反爬**:高,且对频率敏感,易封 IP,务必低频。
- **价值**:用户更专业、讨论质量更高,值得作为第二数据源。

## 3. 新浪财经 🔸(初步评估,待深入验证)

- 有股吧/资讯与评论体系,历史上评论走 `comment*.news.sina.com.cn` 一类 JSON 接口,部分可直接取。
- 站点可达,但具体接口参数与反爬情况本阶段未逐一实测,标为待深入。
- 预计难度中等,值得作为补充数据源调研。

## 4. 同花顺 ⚠️(初步评估,待深入验证)

- 基础页(如 `basic.10jqka.com.cn`)实测返回 **403**,说明有 UA/cookie 层面的反爬。
- 部分数据为 JS 渲染,可能需要浏览器自动化。
- 预计难度中高。

## 5. 淘股吧 / 其他传统论坛 🔸

- 多为传统服务端渲染 HTML,解析相对直接,反爬弱,但数据量与活跃度不如股吧/雪球。
- 可作为补充。

## 6. 微博财经 ⚠️(暂不建议第一版做)

- 移动端 `m.weibo.cn` 有可用接口,但**需要登录后的 cookie**,反爬强、易触发风控。
- 建议放到后续阶段。

---

## 通用注意事项(所有平台)

1. **频率控制**:每次请求后随机 sleep 1~2.5 秒(见 `crawlers/common.py` 的 `polite_get`),既礼貌也降低被封概率。
2. **字段统一**:所有平台映射到同一套字段(`docs/data_schema.md`),便于以后合并分析。
3. **合规**:数据仅用于研究/课程用途,控制频率、不影响目标站正常服务。
4. **易碎性**:网页结构/接口会变,爬虫需要定期维护;优先用内嵌 JSON / 官方接口而非解析易变的 HTML。
