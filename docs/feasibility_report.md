# 各平台爬取可行性报告

> 第一阶段目标:广泛摸清各金融社区平台**能不能爬、能的话怎么爬**,并做出能跑的采集原型。
> 本阶段**不做情绪分析**,但字段按"以后要做情绪分析"来设计(见 `docs/data_schema.md`)。
> 侦察日期:2026-07-04。测试环境为云端(出网走代理),已实测各站可达。

## 结论速览

| 平台 | 可爬性 | 方式 | 需登录/Token | 反爬难度 | 状态 |
|------|--------|------|--------------|----------|------|
| 东方财富股吧 | ✅ 高 | 列表页内嵌 JSON | 否 | 低 | **已做成可跑爬虫** |
| 雪球 | ⚠️ 中低 | 真浏览器过 WAF(推荐);纯 requests 不通;逆向 WAF 脆弱 | 需浏览器 cookie | 高(新版阿里云 WAF) | 原型就绪;实测沙盒采不到,需本地跑 |
| 新浪财经股吧 | ✅ 中 | 列表页静态 HTML(GBK) | 否 | 低 | **已做成可跑爬虫** |
| 同花顺 | ⚠️ 中高 | 页面 + JS 渲染 | 部分需 | 中高(基础页 403) | 初步评估,待深入 |

**推荐第一版主攻东方财富股吧**:最好爬、字段最全、无需登录、量大且都是散户,最贴合"散户舆情"这个目标。雪球质量高但要过 WAF,作为第二优先。

## 1. 东方财富股吧(推荐首选)✅

- **入口**:`https://guba.eastmoney.com/list,{股票代码}.html`,分页为 `list,{代码}_{页码}.html`。
- **关键发现**:列表页静态 HTML 里内嵌一段 `var article_list = {...}` 的 JSON,**每页约 80 条**,直接 `json.loads` 即可,无需解析 DOM,非常稳。
- **能拿到的字段**:帖子 id、标题、作者昵称/ id、**发帖时间(带完整年份)**、阅读数(post_click_count)、评论数、转发数、是否含图/视频,以及平台自带的 `bullish_bearish`(看涨/看跌标记 —— 以后可当情绪的免费参照)。
- **正文**:列表里没有正文,需再请求详情页 `/news,{代码},{帖子id}.html` 抽取(爬虫里 `--with-body` 开关)。
- **登录/Token**:**都不需要**。
- **反爬**:低。带常规浏览器 UA 即可,请求间隔 1~2.5 秒足够礼貌。
- **代码**:`crawlers/eastmoney_guba.py`(已实测跑通,样本见 `data/samples/`)。

## 2. 雪球 ⚠️(已实测,记录多种方法与各自局限)

- **入口**:讨论接口 `https://xueqiu.com/query/v1/symbol/search/status?...&symbol=SZ000001&type=11`。
- **能拿到的字段**(过了 WAF 之后):帖子 id、正文(text,HTML)、作者、发帖时间(毫秒时间戳)、阅读/评论/转发数。
- **价值**:用户更专业、讨论质量更高,值得作为第二数据源。
- **核心障碍**:接口受**新版阿里云 WAF**保护。实测抓到的挑战页含 `aliyun_waf_aa/oo/00` meta 标签、混淆的 `_0x` 变量、一段用 `Function()` 动态执行的 JS,以及一大坨 base64 载荷 —— 属于**JS-VM 型挑战**(需在真实浏览器环境里执行才能拿到放行 cookie)。

下面记录三种方法及**各自的局限**:

### 方法一:真实浏览器自动化(Playwright)——**推荐**
- **原理**:用真实 Chromium 加载页面,像真人一样执行 WAF 的 JS 通过挑战,拿到有效 cookie 后再请求接口 / 解析 DOM。代码见 `crawlers/xueqiu.py` 的 `fetch_via_browser`(已做 Chromium 自动探测 + 代理配置 + 忽略代理 TLS)。
- **优点**:**稳**。WAF 怎么升级,真浏览器都跟着自动过,不需要我们反复破解。
- **局限**:
  1. 依赖能联网的浏览器,比纯接口重(要装 Playwright/Chromium)。
  2. **本云沙盒实测跑不通**:出网走策略代理,`requests` 能走代理,但 **headless Chromium 穿不过该代理**——连 `https://example.com` 都 `ERR_CONNECTION_RESET`。所以**在当前沙盒里采不到雪球样本**。
  3. 雪球反爬对频率敏感,易封 IP,必须低频。
- **怎么才能跑通**:在**普通网络的机器**(如本地电脑,浏览器可直连)上运行 `crawlers/xueqiu.py` 即可正常过 WAF 取样;或后续解决沙盒的"浏览器-代理"连通问题。

### 方法二:纯 requests(不执行 JS)——**不可行**
- **实测**:先访问首页拿到 `acw_tc` cookie,再请求接口,返回的**仍是 WAF 挑战页**(含 `aliyun_waf`/`_waf_`)而非数据。
- **局限**:requests 不会执行 JS,过不了 JS-VM 挑战,拿不到真数据。**此路不通。**

### 方法三:无浏览器执行挑战 JS / 逆向 WAF——**实测跑不通,不推荐**
- **做法**:不开完整浏览器,尝试用 JS 引擎(Node)或轻量 DOM(jsdom)执行那段挑战脚本,算出放行 cookie 后用 requests 重放。
- **实测结果**:
  - 裸 Node 直接执行 → 立刻报 `document is not defined`(挑战依赖浏览器 DOM)。
  - 用 jsdom 提供 DOM 后 → 挑战只执行了一部分(生成了 `window._waf_*` 变量),但**算不出放行 cookie**(`document.cookie` 为空),并卡在 `Not implemented: navigation to another Document`(挑战需要真实页面跳转)。
- **局限**:新版阿里云 WAF 依赖**真实浏览器导航 + 环境指纹**,jsdom 这类会被识破;要真做成,得对高度混淆的 JS-VM 做深度逆向,**工作量大、极脆弱**——阿里云一升级挑战就失效(与反爬的"军备竞赛"),得反复重做。**不推荐。**

### 小结
- **能采到数据的现实路径 = 方法一,在普通网络机器上运行。**
- 方法二不通;方法三理论可行但脆弱、且本环境实测未跑通。

## 3. 新浪财经股吧 ✅(已实测,做成可跑爬虫)

- **入口**:`http://guba.sina.com.cn/?s=bar&name={symbol}&page={n}`,`symbol` 形如 `sz000001` / `sh600519`(交易所前缀+代码)。
- **关键发现**:列表页是 **GBK 编码的静态 HTML**,帖子在一个表格里,每个 `<tr>` 一条,列为:阅读数 | 评论数 | 标题(链接)| 作者 | 时间。标题链接形如 `/?s=thread&tid={tid}&bid={bid}`(class 含 `linkblack`)。直接解析 HTML 即可,无需 JS。
- **正文**:在详情页 `/?s=thread&tid=&bid=` 的 `id="thread_content"` 容器里,需额外请求(`--with-body`)。
- **能拿到的字段**:帖子 id(tid)、标题、正文、作者昵称/id、阅读数、评论数、发帖时间、链接。
- **登录/Token**:**都不需要**。
- **反爬**:低。带常规 UA 即可,仍按 `polite_get` 控制频率。
- **注意**:① 页面是 **GBK**,须 `r.encoding="gbk"` 否则中文乱码;② 列表时间只有 "MM月DD日"(**不带年份**),已原样保留、不臆造。
- **代码**:`crawlers/sina_finance.py`(已实测跑通;样本 `data/samples/sina_sample.csv`,3 只股票各 8 条、全部带正文)。

## 通用注意事项(所有平台)

1. **频率控制**:每次请求后随机 sleep 1~2.5 秒(见 `crawlers/common.py` 的 `polite_get`),既礼貌也降低被封概率。
2. **字段统一**:所有平台映射到同一套字段(`docs/data_schema.md`),便于以后合并分析。
3. **合规**:数据仅用于研究/课程用途,控制频率、不影响目标站正常服务。
4. **易碎性**:网页结构/接口会变,爬虫需要定期维护;优先用内嵌 JSON / 官方接口而非解析易变的 HTML。
