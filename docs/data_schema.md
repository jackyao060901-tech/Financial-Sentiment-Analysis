# 统一数据字段设计

所有平台的采集结果都映射到**同一套字段**,这样以后做情绪分析时,不同平台的数据可以直接拼在一起用。
即使某个平台拿不到某个字段,也**保留该列、留空**,不改变结构。

字段定义见 `crawlers/common.py` 的 `FIELDS`。

| 字段 | 含义 | 说明 |
|------|------|------|
| `platform` | 来源平台 | 如 `eastmoney_guba` / `xueqiu` |
| `stock_code` | 股票代码 | 如 `000001`;雪球用 `SZ000001` 形式 |
| `post_id` | 帖子唯一 id | 用于去重 |
| `title` | 标题 | 雪球无独立标题时取正文前若干字 |
| `content` | 正文 | **情绪分析的主要输入**;股吧需额外请求详情页 |
| `author` | 作者昵称 | |
| `author_id` | 作者 id | |
| `publish_time` | 发帖时间 | 情绪按天聚合时的时间轴 |
| `read_count` | 阅读数 | 可作讨论热度的权重 |
| `comment_count` | 评论数 | 讨论热度 |
| `forward_count` | 转发数 | |
| `bullish_bearish` | 平台自带看涨/看跌标记 | 股吧有,可作情绪的免费参照/校验 |
| `has_pic` | 是否含图 | |
| `has_video` | 是否含视频 | |
| `url` | 帖子链接 | 便于回溯核对 |
| `crawl_time` | 采集时间 | 记录抓取时点 |

## 为什么现在就要定好字段?

老师这一阶段要的是爬虫,但爬虫是为后面的情绪分析服务的。
如果现在不把 `title` / `content` / `publish_time` / `stock_code` 存下来,
以后想做情绪分析时就会发现"爬了也没法用"。所以字段设计要提前对齐目标。

**做情绪分析至少必须有的字段**:`stock_code`、`title`/`content`(文本)、`publish_time`(按天聚合)。
